Architecture · Arm TF-A trusted board boot

Secure boot with Arm TF-A, from ROM to the OS

1BL1 loads BL2At reset the CPU runs BL1 from ROM at EL3, so it can't be modified. BL1 reads the Trusted Boot Firmware certificate and the BL2 image from the FIP in external flash.
2Root-of-trust checkBL1 hashes the public key carried in that certificate and compares it with the ROTPK hash fused into OTP. It then verifies the certificate's signature and checks that BL2's hash matches the one in the certificate. Only then does it jump to BL2, at S-EL1 or at EL3 with RESET_TO_BL2.
3BL2 authenticates the restBL2 reads the Trusted Key certificate, signed by the ROT key, which carries the trusted-world and non-trusted-world public keys. It then checks a key certificate and a content certificate for each image: BL31, BL32 and BL33. Each content certificate holds that image's hash. The work is done by TF-A's authentication framework (chain-of-trust descriptors, mbedTLS crypto, X.509 parser).
—Anti-rollbackEach certificate carries an NV counter. BL2 rejects any certificate whose counter is below the trusted or non-trusted counter in OTP, and can raise the stored counter after a successful update.
4Hand-off to BL31BL2 passes control to BL31, the EL3 runtime. When BL2 runs at S-EL1 this goes through an SMC back to BL1. BL31 stays resident and provides PSCI, SMCCC dispatch and the secure payload dispatcher.
5Bring up both worlds5a: BL31 initialises BL32 (OP-TEE) at S-EL1 through the opteed dispatcher. 5b: it then drops to the normal world with an ERET into BL33 at NS-EL2.
6Chain continues past TF-ABL33 (U-Boot or UEFI) verifies the signed FIT image (hypervisor, kernel, DTB) using public keys embedded in BL33 itself. BL2 already authenticated those keys. The root filesystem is then checked with dm-verity.
✕Failure handlingA bad signature, a hash mismatch or an old NV counter stops the boot, or switches to a backup FIP bank or recovery image. Optional measured boot: BL1 and BL2 record each image's hash in an event log, TPM or RSE so the platform can attest its state later.
